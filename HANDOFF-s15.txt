### 🤔 YOUR QUESTION: "Do we need our own mini RISC-V compiler + kernel?"

**Short answer**: Not yet. Here's the strategy:

#### Current Path (Legacy Linux First) — This Week
```
rvemu (QEMU virt) → Buildroot Linux (Image + rootfs.ext2) → Full userspace
```
- Proves rvemu completeness (VirtIO, MMU, SMP, syscalls)
- Gives us a working Linux environment to run `prisc+x.c` as a Linux binary
- **No custom compiler/kernel needed**

#### Medium-Term Path (Bare-Metal + prisc+x) — This Month
```
rvemu + syscall ABI + newlib/musl → prisc+x.c as bare-metal ELF
```
- Cross-compile newlib or musl for `riscv64-unknown-elf`
- Link `prisc+x.c` → bare-metal ELF → run on rvemu
- **No custom compiler needed** — use upstream GCC + newlib

#### Long-Term Path (Bootstrap from NAND) — The Vision
```
NAND (HDLb0) → RV1 → RV2 → RV4 → RV8 → RV16 → RV32I (HDLb0 design)
                                        ↓
                              rvemu (execution layer)
                                        ↓
                              prisc+x VM (software bridge)
                                        ↓
                              Self-hosting C compiler (written in prisc+x)
                                        ↓
                              Linux kernel (compiled by bootstrapped compiler)
```
- **Custom compiler YES** — but written IN prisc+x, not C
- **Custom kernel YES** — but compiled BY the bootstrapped compiler
- HDLb0 is for VERIFICATION/EDUCATION; rvemu is for EXECUTION
